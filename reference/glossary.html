基础概念

LLM Large Language Model 大语言模型

在海量文本上训练的深度学习模型，能够理解和生成人类语言。代表：GPT-4、Claude、Gemini、Llama。作为 AI Engineer，你通过 API 使用它，不需要训练它。

首见: Lesson 0001 · 相关: Prompt, Completion, Token

Prompt Prompt 提示词

发送给 LLM 的输入文本。包含你的指令、问题、上下文等。Prompt 的质量直接决定 LLM 输出的质量。

首见: Lesson 0001 · 相关: Completion, Prompt Template

Completion Completion 补全/生成结果

LLM 根据 Prompt 生成的输出文本。也叫 response 或 generation。

首见: Lesson 0001 · 相关: Prompt, Token

Token Token 令牌/标记

LLM 处理文本的最小单位。大约 4 个英文字符 = 1 token，1 个中文字 ≈ 1-2 tokens。API 按 token 计费，也有 context window（上下文窗口）的 token 数量限制。

首见: Lesson 0001 · 相关: Context Window

Context Window Context Window 上下文窗口

LLM 一次能处理的最大 token 数量。包含输入（prompt）和输出（completion）的总和。GPT-4 通常是 128K tokens，Claude 可达 200K tokens。这是 RAG 存在的原因之一 — 你不能把所有文档都塞进 context window。

首见: Lesson 0001 · 相关: Token, RAG

API 调用相关

Chat Completion Chat Completion API 聊天补全 API

LLM 的核心 API 接口。接收一个 messages 数组，返回模型生成的回复。每次调用都是无状态的 — LLM 不记得上一次请求，所以你必须每次都发送完整的对话历史。

首见: Lesson 0002 · 相关: Messages 数组, Temperature, Token

Messages 数组 Messages Array 消息数组

Chat API 的输入格式。包含多条消息，每条有 role（system / user / assistant）和 content。system 定义行为规则，user 是用户输入，assistant 是模型历史回复。三者组合构成完整的对话上下文。

首见: Lesson 0002 · 相关: Chat Completion, Prompt

Temperature Temperature 温度

控制 LLM 输出随机性的参数。0 = 最确定性（每次回答几乎相同），2 = 最随机。RAG 场景通常用低温度（0–0.3）以获得准确、一致的回答；创意写作用高温度（0.7–1.0）。

首见: Lesson 0002 · 相关: Chat Completion

OpenAI Compatible API OpenAI Compatible API OpenAI 兼容 API

许多 LLM 厂商（DeepSeek、智谱、Moonshot 等）采用与 OpenAI 相同的 API 格式。只需用 openai Python 包，切换 base_url 和 api_key 即可调用不同厂商的模型。这已成为行业事实标准。

首见: Lesson 0002 · 相关: Chat Completion, Embedding

RAG 相关

Embedding Embedding / Vector Embedding 嵌入/向量嵌入

把文本（或其他数据）转换成一个高维度的数字向量（embedding-3 = 2048 维）。它不是意义的"哲学编码"，而是意义的统计学代理——模型经对比训练（contrastive training）学到一个映射：人类觉得相似的文本在向量空间里靠近，无关的推开，于是 cosine 距离 ≈ 语义相似度。

关键性质：① 有损——任意长度文本压成定长向量必然丢信息，是个语义指纹；② 维度不可解释——各维是潜变量、分布式（latent / distributed），没有"第 1 维=情感"这种含义，语义住在整个向量的方向里（类比 JPEG 系数，非 RGB 像素）；支持指定维度的模型用 Matryoshka 表示学习，靠前的维度承载更多通用语义，但单维仍不可解释；③ 归一化——返回前 L2 归一化，向量落在单位超球面（norm=1），故 cosine ∈ [-1, 1]。

局限与陷阱：embedding 擅长主题相似，弱于精细句法、逻辑方向、否定（"A 打败 B" vs "B 打败 A" 常分不清）；任何字符串都有向量，连无意义 token 拼接也能得到 ~0.5 的相似度，可能骗过阈值门控——所以门控只是防幻觉第一道防线。实测见 src/teach_ai/09_embedding_probe.py，详解见 学习记录 0006。

首见: Lesson 0001 · 相关: Vector Database, Cosine Similarity

Vector Database Vector Database / Vector Store 向量数据库

专门存储和检索向量的数据库。支持高效的相似度搜索（"找到和这个向量最接近的 K 个向量"）。常见：ChromaDB（轻量/入门）、Pinecone（云服务）、FAISS（Facebook 出品，高性能）。

首见: Lesson 0001 · 相关: Embedding, RAG, ANN

ANN Approximate Nearest Neighbor 近似最近邻

向量数据库用来加速检索的索引算法（ChromaDB 用 HNSW）。不保证找到全局最优解，但用极小的精度损失换取近似 O(log n) 的检索速度（对比暴力搜索的 O(n)）。在 RAG 场景里这点近似完全可以接受。

局限：ANN 是在已经有损的 embedding 之上再近似一层，加上 embedding 本身弱于精细语义 → 检索结果可能"主题对、细节错"。所以生产 RAG 在 ANN 之后还要 rerank（重排） + 相似度阈值兜底，而非直接信任 top-k。

首见: Lesson 0003 · 相关: Vector Database, Cosine Similarity

RAG Retrieval-Augmented Generation 检索增强生成

一种架构模式：先从知识库中检索（Retrieve）相关文档，然后用这些文档增强（Augment） prompt，最后让 LLM 生成（Generate）回答。解决 LLM 不了解私有数据/最新信息的问题。

首见: Lesson 0001 · 相关: Embedding, Vector Database, Chunking

Chunking Chunking / Text Splitting 文本切分

把长文档切分成小段（chunks），每段独立向量化并存入向量数据库。切分策略（按段落、按句子、按固定字数、递归切分等）直接影响检索质量。理想 chunk 主题单一且语义完整 —— 太大则一个 chunk 混杂多主题、检索不精准；太小则上下文碎片化。相邻 chunk 可保留 overlap（重叠）以避免在边界切断关键信息。

首见: Lesson 0003 · 相关: RAG, Embedding

Cosine Similarity Cosine Similarity 余弦相似度

衡量两个向量方向一致程度的指标，值域 [-1, 1]。1 = 完全相同方向（最相似），0 = 正交（无关），-1 = 完全相反。在 RAG 检索中用于找到与查询最相似的文档。

相关: Embedding, Vector Database

LangChain / LangGraph 相关

LangChain LangChain —

一个用于构建 LLM 应用的 Python 框架。提供 Prompt Templates、Output Parsers、Tool Calling、Document Loaders 等组件，用 LCEL 组合它们。核心抽象：每个组件都是 Runnable，接口统一（都有 .invoke()），所以能像积木一样任意串联。langchain-openai 是接 OpenAI 兼容模型（如 DeepSeek）的子包。

首见: Lesson 0005 · 相关: LCEL, Runnable, LangGraph

LCEL LangChain Expression Language LangChain 表达语言

LangChain 中用 |（pipe 管道符）将组件串联的声明式语法。prompt | llm | parser 表示"先填模板、再调模型、最后解析输出"——上一个组件的输出自动喂给下一个，和 Unix 管道 cat | grep | sort 同理。串联结果是一个 RunnableSequence，用 .invoke({...}) 触发整条链。

首见: Lesson 0005 · 相关: LangChain, Prompt Template, Output Parser, Runnable

LangGraph LangGraph —

基于 LangChain 的框架，用有状态图（Stateful Graph）编排复杂的 AI 工作流。每个节点（Node）是一个处理步骤，边（Edge）定义流转。支持条件分支、循环、状态持久化和人工介入。

相关: LangChain, StateGraph, Agent

StateGraph StateGraph 状态图

LangGraph 的核心数据结构。定义一个图，包含状态（State）、节点（Nodes）和边（Edges）。每次执行时，状态在节点之间传递和更新。

相关: LangGraph

Prompt Template Prompt Template 提示词模板

一个带有占位符的 prompt 格式。运行时用实际数据填充占位符，生成完整的 prompt。类似 Python 的 f-string，但模板是独立对象——可复用、可校验、可塞进 LCEL 链里。构造：ChatPromptTemplate.from_messages([("system", "..."), ("user", "{question}")])，占位符 {question} 在 .invoke({"question": ...}) 时填入。

首见: Lesson 0005 · 相关: Prompt, LCEL

Output Parser Output Parser / StrOutputParser 输出解析器

把 LLM 返回的结构化输出（AIMessage）转换成你想要的形式的组件。StrOutputParser() 最简单：直接抠出 .content 的纯文本（对应手写代码里的 response.choices[0].message.content）。更复杂的 parser 能把文本解析成 JSON / Pydantic 对象、列表等。它是 LCEL 链 prompt | llm | parser 的最后一环。

首见: Lesson 0005 · 相关: LCEL, LangChain

Runnable Runnable 可运行组件

LangChain 的核心协议/接口。prompt、llm、parser、retriever、整条 chain —— 每一个都是 Runnable，都有统一的 .invoke(input)（还有 .batch()、.stream()、.ainvoke() 异步等）。正是因为接口统一，任何 Runnable 的输出都能直接接另一个的输入，才能用 | 随意串联（LCEL）。串联后的整体叫 RunnableSequence，它本身也是 Runnable。

首见: Lesson 0005 · 相关: LCEL, LangChain

Tool Calling Tool Calling / Function Calling 工具调用

让 LLM 决定是否需要调用外部工具（函数），并生成调用所需的参数。LLM 不直接执行工具 — 它只生成调用请求，由应用层执行。这是 Agent 的基础能力。

相关: Agent, ReAct

Agent 相关

Agent AI Agent / Autonomous Agent 智能体

一个能自主决定行动步骤的 LLM 应用。Agent 在一个循环中运行：观察 → 思考 → 行动 → 观察 → …直到任务完成。你使用的 Claude Code 就是一个典型的 Agent。

首见: Lesson 0001 · 相关: ReAct, Tool Calling

ReAct ReAct (Reasoning + Acting) 推理-行动模式

一种常见的 Agent 模式：LLM 先推理（Reasoning）当前应该做什么，然后行动（Acting）执行操作，观察结果后再推理下一步。是最基础也最常用的 Agent 设计模式。

相关: Agent, Tool Calling

Human-in-the-Loop Human-in-the-Loop (HITL) 人工介入

在 Agent 的工作流中设置检查点，暂停执行，等待人工审核或确认后再继续。用于关键决策步骤，确保 AI 不会自主执行高风险操作。

相关: Agent, LangGraph

文档加载与切分

Document Document (LangChain) 文档对象

LangChain 中表示一段文本的核心数据结构。包含两个字段：page_content（文本内容，str）和 metadata（元数据字典，如来源文件路径、页码等）。RAG 全流程中的数据载体——从 Document Loader 加载到 Text Splitter 切分再到 VectorStore 存储，都围绕这个对象流转。

首见: Lesson 0007 · 相关: Document Loader, RecursiveCharacterTextSplitter

Document Loader Document Loader 文档加载器

从各种来源（本地文件、网页、数据库、API）将数据加载为 Document 对象的组件。最简单的 TextLoader 把文件内容原样读入一个 Document，自动将文件路径写入 metadata["source"]。其他常用：DirectoryLoader（批量加载目录）、UnstructuredMarkdownLoader（按元素解析 Markdown）。

注意：TextLoader 目前在 langchain-community 包中，但该包正在被 sunset。功能极简，底层就是 open().read() + 包装 Document。

首见: Lesson 0007 · 相关: Document, Chunking

RecursiveCharacterTextSplitter RecursiveCharacterTextSplitter (RCTS) 递归字符文本切分器

LangChain 最常用的文本切分器。按分隔符优先级列表从粗到细递归切分文本：先按段落（\n\n），太大就降到行（\n），再降到句号/空格/逐字符。关键参数：

  • chunk_size：每个 chunk 的最大字符数
  • chunk_overlap：相邻 chunk 重叠的字符数，防止边界处丢失上下文
  • separators：分隔符优先级列表。中文文档需补 "。" 等标点，否则会从段落直接跳到空格

手写 text.split("\n\n") 相当于只用了 RCTS 的第一级分隔符，且无 chunk_size 限制和 overlap。
