VectorStore Retriever 与 RunnablePassthrough

⏱️ 约 30–40 分钟 动手课 📅 Week 2
💡 为什么我们要手写一遍再用框架？

在 Week 1，你写了 60 行代码实现了 TrustRAG.retrieve() 和 ask()，自己计算相似度并实现了门控。现在，我们要用 LangChain 的核心组件把这段逻辑压缩到几行。因为你手写过，你会看穿：LangChain 没有做任何魔法，它只是把你写过的循环和条件判断，封装成了标准组件。

知识 ①：把向量库变成 Retriever (检索器)

在手写版的 rag.py 里，你的检索逻辑是：

query_vec = self._embed([query])[0]
results = self.collection.query(query_embeddings=[query_vec], n_results=k)
# 然后把 distance 转换成 similarity
sims = [1 - dist for dist in results["distances"][0]]
# 门控：判断 sims[0] < SIM_THRESHOLD

LangChain 提供了一个专门包 langchain-chroma。只需两步，它就能替你干完上面所有的活：

from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings

# 1. 连上你 Week 1 的数据库（数据还在！）
vectorstore = Chroma(
    collection_name="trust_docs",
    embedding_function=OpenAIEmbeddings(...),
    persist_directory="./chroma_db",
)

# 2. 把它变成一个标准的 Retriever，并自带相似度门控
retriever = vectorstore.as_retriever(
    search_type="similarity_score_threshold",
    search_kwargs={"score_threshold": 0.5, "k": 3}
)

这个 retriever 是一个标准的积木（实现了 Runnable 接口）。只要给它传一个字符串 "什么是编码规范检查？"，它就会吐出大于 0.5 分的文档列表。如果都低于 0.5 分，它就直接返回空列表 []。

⚠️ 深坑预警：OpenAIEmbeddings 与非 OpenAI 模型

在刚才的 10_rag_lcel.py 中，你可能注意到我们在 OpenAIEmbeddings 里加了一行 check_embedding_ctx_length=False。这是一个极其经典的 AI 工程大坑！

如果不加这行，LangChain 默认会以为你在用原版 OpenAI，于是私下用 OpenAI 的 tiktoken 分词器把你的中文（比如"什么是..."）切成了 token 整数数组（如 [6271, 222, ...]）发给智谱 API。智谱拿到一堆整数完全看不懂，直接把它们当成无意义乱码进行了 embedding 计算！这导致算出来的向量和原本的文本十万八千里，相似度暴跌到 0.2，直接被 0.5 的阈值无情拦截。加上这行参数后，LangChain 就会老老实实发送原始字符串了。

知识 ②：LCEL 兵分两路 —— RunnablePassthrough

有了 retriever，再加上我们在 Lesson 5 学的 prompt | llm | parser，怎么把它们拼成一条完整的 RAG 链？

难点在于：prompt 需要两个占位符变量：{context} 和 {question}。但最开始用户的输入只有一个字符串，比如 "什么是编码规范检查？"。

所以，我们需要在输入 prompt 之前，把数据兵分两路：

  • 左路（给 context 填值）：把查询词交给 retriever 去找文档，找到后拼成一大段文本。
  • 右路（给 question 填值）：什么都不干，把查询词原样透传过去。

在 LCEL 中，用字典就能实现这种并行处理：

from langchain_core.runnables import RunnablePassthrough

def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)

# 并行数据准备
setup_and_retrieval = {
    "context": retriever | format_docs,   # 左路：检索 -> 拼文本
    "question": RunnablePassthrough()     # 右路：原样透传
}
                      /-- [retriever | format_docs] --\
"问题字符串" -> 兵分两路                                 字典: {"context": 文本, "question": 问题} -> prompt
                      \-- [RunnablePassthrough()] ----/

图 1：用字典和 RunnablePassthrough 并行准备 Prompt 数据

至此，数据变成了 prompt 需要的字典格式，后面只要 | prompt | llm | parser 一把梭就完事了。
