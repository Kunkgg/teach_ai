Lesson 0002

第一次 LLM API 调用：Chat + Embedding

用 DeepSeek 做对话，用智谱做向量化 — 两个 API，一个 SDK

⏱️ 约 30 分钟 动手课 📅 Week 1 · Day 1–2

为什么从 API 调用开始？

RAG pipeline 的每一个环节最终都要调用 LLM 的 API。如果你不理解 Chat Completion 和 Embedding 这两个核心 API 的工作方式，后面学 LangChain、LangGraph 时你会觉得"框架在替我做魔法" — 这是最危险的。

这节课的目标很明确：

  1. Chat Completion — 给 LLM 发消息，拿到回复（用 DeepSeek）
  2. Embedding — 把文本变成向量（用智谱）
  3. 余弦相似度 — 用数学衡量两段文本"有多像"
💡 关键认知

DeepSeek 和智谱的 API 都是 OpenAI 兼容的。这意味着你只需要安装 openai 这一个 Python 包，通过切换 base_url 和 api_key 就能调用不同厂商的模型。这不是巧合 — OpenAI 的 API 格式已经成为行业事实标准。

你的 API 配置清单

在开始写代码之前，确认你有以下信息：

厂商 用途 base_url 模型名
DeepSeek Chat 对话 https://api.deepseek.com deepseek-v4-flash
智谱 Embedding 向量化 https://open.bigmodel.cn/api/paas/v4/ embedding-3
⚠️ 关于 DeepSeek 模型名

旧的 deepseek-chat 和 deepseek-reasoner 已在 2026 年 7 月下线。现在用 deepseek-v4-flash（通用任务）或 deepseek-v4-pro（复杂推理）。如果你不确定，登录 DeepSeek Platform 查看最新模型列表。

💡 为什么 Embedding 用智谱？

因为 DeepSeek 没有 Embedding API — 它只提供 Chat 类模型。在 RAG 中，Chat 模型和 Embedding 模型来自不同厂商是完全正常的。你甚至可以用智谱的 Embedding + DeepSeek 的 Chat 来搭建你的 RAG pipeline — 下节课我们就会这么做。

知识 ①：Chat Completion API

核心概念：Messages 数组

Chat API 不是"发一句话、回一句话"这么简单。它接收的是一个 messages 数组，其中每条消息都有一个 role（角色）：

role 含义 用途
system 系统指令 设定 LLM 的行为规则和角色定义
user 用户输入 你（或你的应用用户）发送的消息
assistant 模型回复 LLM 之前的回复，用于多轮对话

这三个 role 的组合就是 LLM 对话的全部。你每次都要发送 完整的对话历史，因为 LLM 本身是 无状态的 — 它不记得上一次请求。

🎯 和可信看板的关系

以后你的可信看板 RAG 系统会这样工作：system message 设定"你是一个可信工程助手"，user 发送用户的查询 + 检索到的文档，assistant 返回基于文档的回答。理解 messages 数组是一切的起点。

Task ①：调用 DeepSeek Chat API

1 动手：第一次 Chat Completion 调用

目标：用 Python 调用 DeepSeek API，完成一次对话。

  1. 安装依赖（如果还没装过）：

    pip install openai

  2. 创建文件 01_chat.py，写入以下代码：

    from openai import OpenAI

# 创建 DeepSeek 客户端 — 只需改 base_url 和 api_key
client = OpenAI(
    api_key="你的-DeepSeek-API-Key",     # ← 替换成你的 key
    base_url="https://api.deepseek.com",
)

# 发送 Chat Completion 请求
response = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[
        {
            "role": "system",
            "content": "你是一个可信工程助手，帮助开发者理解编码规范和可信构建流程。"
        },
        {
            "role": "user",
            "content": "什么是编码规范检查？用一句话解释。"
        },
    ],
    temperature=0.3,    # 低温度 = 更确定性的回答
    max_tokens=200,     # 限制回复长度
)

# 提取回复内容
answer = response.choices[0].message.content
print(f"模型回复: {answer}")
print(f"消耗 tokens: {response.usage.total_tokens}")

  3. 运行它：

    python 01_chat.py
✅ 检查点：你应该看到

模型用一句话解释了"编码规范检查"，并打印出 token 消耗量（通常 100–300 tokens）。如果报错 AuthenticationError，检查你的 API key 是否正确。

代码解析：三个你必须理解的参数

参数 含义 常用值
temperature 控制输出的随机性。0 = 最确定，2 = 最随机 RAG 用 0–0.3，创意写作用 0.7–1.0
max_tokens 回复的最大 token 数。注意是 回复，不是总量 一般 200–2000，看场景
messages 完整的对话上下文，必须包含 role 和 content 至少一条 user message
💡 Token 是什么？

Token ≈ 词的碎片。英文中 1 token ≈ 4 个字符，中文中 1 个汉字通常 = 1–2 个 token。API 按 token 计费。你在 response.usage 里能看到精确的 token 数：prompt_tokens（输入）+ completion_tokens（输出）= total_tokens。

知识 ②：Embedding API

从直觉到数学

Embedding 是 RAG 的核心技术。它做一件事：把文本变成一组数字（向量），使得含义相近的文本在数学空间中距离更近。

文本                          向量 (简化为 3 维)
──────────────────            ─────────────────────
"Python 编程教程"      →      [0.82, 0.15, 0.71]
"Python 开发入门"      →      [0.80, 0.17, 0.69]  ← 和上面很接近！
"今天天气不错"         →      [0.12, 0.93, 0.08]  ← 完全不同

图 1：语义相似的文本 → 距离相近的向量

实际的 Embedding 模型输出的向量维度远不止 3 维。智谱的 embedding-3 默认输出 2048 维。维度越高，区分能力越强，但也更占空间。

Task ②：调用智谱 Embedding API

2 动手：把文本变成向量

目标：用智谱的 Embedding API 把文本转成向量，观察输出结构。

  1. 创建文件 02_embedding.py，写入以下代码：

    from openai import OpenAI

# 创建智谱客户端 — 同样的 openai 包，不同的 base_url
client = OpenAI(
    api_key="你的-智谱-API-Key",                          # ← 替换
    base_url="https://open.bigmodel.cn/api/paas/v4/",
)

# 调用 Embedding API
response = client.embeddings.create(
    model="embedding-3",
    input="什么是编码规范检查？",
)

# 提取向量
vector = response.data[0].embedding

print(f"向量维度: {len(vector)}")
print(f"前 10 个数值: {vector[:10]}")
print(f"消耗 tokens: {response.usage.total_tokens}")

  2. 运行它：

    python 02_embedding.py
✅ 检查点：你应该看到

向量维度 = 2048，前 10 个数值是类似 [0.0123, -0.0456, ...] 的浮点数。每个数值都在 -1 到 1 之间。

Embedding API 与 Chat API 的关键区别

Chat Completion API Embedding API
输入 messages 数组（多轮对话） 单个字符串或字符串数组
输出 生成的文本（自然语言回复） 浮点数数组（向量）
用途 对话、推理、生成、总结 语义搜索、相似度计算、聚类
成本 较高（按输入+输出 token） 很低（智谱约 0.5元/百万 token）

知识 ③：余弦相似度

有了向量，怎么衡量两段文本"有多像"？用余弦相似度（Cosine Similarity）。

你不需要理解推导。只需要记住：

  • = 1：完全相同的含义
  • ≈ 0.8–0.9：含义高度相关
  • ≈ 0.5–0.7：有一些关联
  • ≈ 0–0.3：基本无关
🎯 为什么这很重要？

RAG 的核心就是：用户提问 → 把问题转成向量 → 在向量数据库中找到余弦相似度最高的文档片段 → 把这些片段塞到 prompt 里 → 让 LLM 回答。余弦相似度就是"搜索"的数学基础。

Task ③：计算余弦相似度

3 动手：衡量文本相似度

目标：对 4 段文本做 Embedding，计算两两之间的余弦相似度，验证"语义相近 → 相似度高"。

  1. 创建文件 03_similarity.py，写入以下代码：

    from openai import OpenAI

client = OpenAI(
    api_key="你的-智谱-API-Key",
    base_url="https://open.bigmodel.cn/api/paas/v4/",
)

# 四段测试文本 — 故意设计了两对"含义相近"的
texts = [
    "编码规范检查是对源代码进行静态分析的过程",       # A: 编码规范
    "代码审查用于发现代码中的质量问题和规范违规",       # B: 代码审查（和 A 相关）
    "可信构建确保软件构建过程的完整性和可追溯性",       # C: 可信构建
    "今天的天气真好，适合出去散步",                   # D: 无关内容
]

# 批量获取 Embedding（一次 API 调用搞定）
response = client.embeddings.create(
    model="embedding-3",
    input=texts,
)

# 提取向量列表
vectors = [item.embedding for item in response.data]


# 计算余弦相似度（不依赖外部库）
def cosine_similarity(vec_a, vec_b):
    dot_product = sum(a * b for a, b in zip(vec_a, vec_b))
    norm_a = sum(a * a for a in vec_a) ** 0.5
    norm_b = sum(b * b for b in vec_b) ** 0.5
    return dot_product / (norm_a * norm_b)


# 打印相似度矩阵
labels = ["A:编码规范", "B:代码审查", "C:可信构建", "D:天气"]
print(f"{'':>12}", end="")
for label in labels:
    print(f"{label:>12}", end="")
print()

for i, row_label in enumerate(labels):
    print(f"{row_label:>12}", end="")
    for j in range(len(labels)):
        sim = cosine_similarity(vectors[i], vectors[j])
        print(f"{sim:>12.4f}", end="")
    print()

  2. 运行它：

    python 03_similarity.py
✅ 检查点：你应该看到的模式

A（编码规范）和 B（代码审查）的相似度应该 明显高于 它们和 D（天气）的相似度。这验证了 Embedding 确实在捕捉语义。典型结果：A↔B ≈ 0.75–0.85，A↔D ≈ 0.15–0.35。

Task ④：用不同厂商组合完成端到端流程

4 动手：智谱 Embedding + DeepSeek Chat = Mini RAG

目标：模拟 RAG 的核心流程 — 用 Embedding 找到最相关的文档，然后让 Chat 模型基于文档回答。

  1. 创建文件 04_mini_rag.py，写入以下代码：

    from openai import OpenAI

# 两个客户端 — 不同厂商，同一个 SDK
zhipu = OpenAI(
    api_key="你的-智谱-API-Key",
    base_url="https://open.bigmodel.cn/api/paas/v4/",
)
deepseek = OpenAI(
    api_key="你的-DeepSeek-API-Key",
    base_url="https://api.deepseek.com",
)

# ── Step 1: 准备"知识库"（3 段文档） ──
documents = [
    "编码规范检查通过静态分析工具（如 ESLint、Pylint）自动扫描源代码，"
    "识别不符合团队编码规范的代码模式，包括命名规范、代码格式、复杂度等。",

    "可信构建是指在可控、可追溯的环境中执行软件构建，"
    "确保构建产物与源代码的对应关系可验证，防止供应链攻击。",

    "代码度量通过量化指标（如圈复杂度、代码行数、重复率）"
    "评估代码质量，帮助团队识别需要重构的高风险模块。",
]

# ── Step 2: 用智谱把文档 + 查询都变成向量 ──
query = "我们的代码规范检查具体检查哪些方面？"

# 批量 embedding：文档 + 查询一起发
all_texts = documents + [query]
emb_response = zhipu.embeddings.create(
    model="embedding-3",
    input=all_texts,
)
all_vectors = [item.embedding for item in emb_response.data]

doc_vectors = all_vectors[:3]      # 前 3 个是文档向量
query_vector = all_vectors[3]      # 最后一个是查询向量

# ── Step 3: 找到最相关的文档（余弦相似度） ──
def cosine_similarity(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    norm_a = sum(x * x for x in a) ** 0.5
    norm_b = sum(x * x for x in b) ** 0.5
    return dot / (norm_a * norm_b)

scores = []
for i, doc_vec in enumerate(doc_vectors):
    sim = cosine_similarity(query_vector, doc_vec)
    scores.append((sim, i))
    print(f"文档 {i+1} 相似度: {sim:.4f}")

# 取相似度最高的文档
scores.sort(reverse=True)
best_idx = scores[0][1]
best_doc = documents[best_idx]
print(f"\n最相关文档: 文档 {best_idx + 1}")
print(f"内容: {best_doc}\n")

# ── Step 4: 用 DeepSeek 基于文档回答问题 ──
chat_response = deepseek.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[
        {
            "role": "system",
            "content": "你是一个可信工程助手。请仅基于提供的参考文档回答问题，"
                       "不要编造信息。如果文档中没有相关信息，请明确说明。"
        },
        {
            "role": "user",
            "content": f"参考文档:\n{best_doc}\n\n问题: {query}"
        },
    ],
    temperature=0.2,
    max_tokens=300,
)

print("─" * 50)
print(f"问题: {query}")
print(f"回答: {chat_response.choices[0].message.content}")

  2. 运行它：

    python 04_mini_rag.py
✅ 检查点

程序应该自动选中"文档 1"（编码规范相关），然后 DeepSeek 基于这段文档给出回答。这就是 RAG 的完整流程 — 只不过我们目前的"向量数据库"是一个 Python list，下一课我们会换成真正的向量数据库。

知识检验

确认你理解了核心概念：

Q1: 为什么 DeepSeek 和智谱的 API 可以用同一个 openai Python 包调用？

Q2: LLM 的 Chat API 为什么每次都要发送完整的 messages 数组？

Q3: 在 Task ④ 的 Mini RAG 中，哪一步最接近 RAG 中的"Retrieval"？

Q4: temperature=0.2 和 temperature=0.9 哪个更适合 RAG 中的回答生成？

今天学到了什么

  1. Chat Completion API 接收一个 messages 数组（system/user/assistant），LLM 是无状态的
  2. Embedding API 把文本转成高维向量，语义相近 → 向量距离近
  3. 余弦相似度可以衡量两段文本的语义相关性（1 = 完全相同，0 = 无关）
  4. DeepSeek 和智谱都是 OpenAI 兼容的，用同一个 openai 包即可
  5. 不同厂商的模型可以混用 — 智谱做 Embedding，DeepSeek 做 Chat，这在 RAG 中很常见

下一课预告

这节课的 Mini RAG 用的是 Python list 作为"知识库"。但如果你有 1000 篇文档、每篇切成 20 个片段，就是 20000 个向量 — 用 list 遍历计算相似度太慢了。
