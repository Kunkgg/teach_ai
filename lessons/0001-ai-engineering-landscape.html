为什么是 AI 工程而不是 AI 研究

你需要先理解一个关键区分：AI Researcher（AI 研究员）和 AI Engineer（AI 工程师）是两条完全不同的职业路径。

AI Researcher AI Engineer
核心工作 设计新的模型架构和算法 用现有模型构建应用和系统
数学要求 线性代数、概率论、优化理论 理解概念即可，不需推导
编程重点 PyTorch、模型训练、GPU 优化 API 集成、Pipeline 编排、系统设计
典型产出 论文、新模型、benchmark 可运行的 AI 应用、RAG 系统、Agent
学历要求 通常需要硕/博 项目经验 > 学历

核心概念速览

在正式开始之前，你需要理解 5 个核心概念。这些概念会贯穿整个学习过程。

1. LLM（Large Language Model，大语言模型）

你已经在使用 Claude Code — Claude 就是一个 LLM。LLM 的本质是一个文本补全机器：给它一段文本（prompt），它生成下一段文本（completion）。作为 AI Engineer，你不需要知道它内部怎么运作，你只需要知道如何通过 API 高效地使用它。

2. Embedding（嵌入/向量化）

把文本转换成一组数字（向量），使得含义相似的文本在数学空间中距离更近。比如 "Python 编程" 和 "Python 开发" 的向量会很接近，而 "Python 蟒蛇" 的向量会远一些。这是 RAG 的基础。

3. RAG（Retrieval-Augmented Generation，检索增强生成）

LLM 只知道训练时见过的数据。RAG 让你在调用 LLM 之前先检索相关文档，把检索到的内容塞到 prompt 里，让 LLM 基于你的私有数据回答问题。

🎯 和可信看板的关系

你的可信看板有大量的规范文档和扫描数据。RAG 可以让用户用自然语言查询这些数据："最近一次版本发布中，哪些组件的编码规范检查没通过？" — LLM 会检索相关数据，给出准确回答。

4. Agent（智能体）

一个 Agent 是一个能自主决定下一步做什么的 LLM 应用。和简单的 "问→答" 不同，Agent 可以：

  • 观察环境（读取数据、API 返回值）
  • 思考下一步（LLM 推理）
  • 执行动作（调用工具、执行代码）
  • 循环以上步骤直到任务完成

你每天用的 Claude Code 就是一个 Agent — 它读代码、分析问题、调用工具、写代码，循环直到完成。

5. LangGraph

LangGraph 是一个框架，用图（Graph）来编排复杂的 AI 工作流。每个节点（Node）是一个处理步骤，边（Edge）定义流转逻辑。和简单的线性 Chain 不同，LangGraph 支持：

  • 条件分支（Conditional Routing）
  • 循环（Loops）
  • 状态持久化（State Checkpointing）
  • 人工介入（Human-in-the-Loop）
