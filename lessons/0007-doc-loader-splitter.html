Lesson 0007

从 split("\n\n") 到智能切分

Document Loaders + RecursiveCharacterTextSplitter

⏱️ 约 25–35 分钟 动手课 📅 Week 2

Week 1 的遗留问题

回忆 Lesson 0003，你手写了这行切分逻辑：

chunks = [p.strip() for p in text.split("\n\n") if p.strip()]

问题很明显：

  1. 文档写死在代码里——真实场景的文档是 .md / .pdf / .txt 文件，不可能全部硬编码
  2. 切分粒度不可控——split("\n\n") 只管段落边界，一段如果 500 字，就直接 500 字塞进向量库
  3. 没有来源追踪——chunk 丢失了它来自哪个文件、哪一行

本课用 LangChain 的两个标准组件一次解决这三个问题。

知识 ①：Document Loader — 从文件到 Document

LangChain 的 Document 对象有两个字段：

  • page_content：文本内容（str）
  • metadata：元数据字典（来源文件路径、页码等）

Document Loader 负责从各种来源（本地文件、网页、数据库）把数据装进 Document 对象。最简单的是 TextLoader，把文件内容原样读入：

from langchain_community.document_loaders import TextLoader

loader = TextLoader("src/teach_ai/trust_spec.md", encoding="utf-8")
docs = loader.load()   # → [Document(page_content="# 可信...", metadata={"source": "..."})]

一个 .load() 调用，你就拿到了带 metadata 的 Document——后续 RAG 回答时可以告诉用户"这个信息来自哪个文件"。

⚠️ 关于 langchain-community 的未来

langchain-community 正在被 LangChain 团队逐步废弃（sunset），未来各集成会拆成独立包。TextLoader 功能简单，官方甚至建议直接用 Python 原生代码替代：

from langchain_core.documents import Document

with open("trust_spec.md", encoding="utf-8") as f:
    docs = [Document(page_content=f.read(), metadata={"source": "trust_spec.md"})]

本课仍用 TextLoader 讲解，因为它是 LangChain 生态的标准模式——面试和项目中会大量看到。但你要知道它底层就这么几行 Python。

知识 ②：RecursiveCharacterTextSplitter — 层级递归切分

split("\n\n") 只按一种分隔符切。RecursiveCharacterTextSplitter（以下简称 RCTS）则按优先级从高到低依次尝试多种分隔符：

separators = ["\n\n", "\n", "。", " ", ""]
#              段落 → 换行 → 句号 → 空格 → 逐字符
#                    ← 优先用左边的，切不到 chunk_size 才降级 →

算法逻辑：

  1. 先用 "\n\n"（段落）切一刀
  2. 如果某段超过 chunk_size（如 200 字符），就用下一个分隔符 "\n" 再切
  3. 还是太大？降到 "。" 切
  4. 直到每一段都 ≤ chunk_size

这就是名字里 "Recursive" 的含义——递归地尝试更细的分隔符，直到满足大小限制。

原文（739字符）
    │
    ▼  第 1 轮：按 "\n\n" 切
┌───────────────────┐
│ 段落1: 130字 ✅    │  ≤ 200，直接过
│ 段落2: 108字 ✅    │  ≤ 200，直接过
│ 段落3: 175字 ✅    │  ≤ 200，直接过
│ 段落4: 180字 ✅    │  ≤ 200，直接过
│ 段落5: 157字 ✅    │  ≤ 200，直接过
└───────────────────┘

如果某段 > 200 字符呢？
    │
    ▼  第 2 轮：对超大段按 "\n" 切
    ▼  第 3 轮：还大？按 "。" 切
    ▼  ...逐级降级

图 1：RCTS 的递归切分逻辑——先粗后细，保持语义完整

两个关键参数：

  • chunk_size=200：每段不超过 200 字符
  • chunk_overlap=30：相邻 chunk 重叠 30 字符。为什么？ 假设"可信构建要求..."在 chunk A 结尾被切断，overlap 保证 chunk B 开头会重复这句的尾部，避免检索时丢失边界处的信息
💡 对照 Week 1

split("\n\n") 相当于只用了 RCTS 的第一层分隔符，且没有 chunk_size 限制、没有 overlap。RCTS 做的事 = 你手写代码的通用化升级。

卡住了？点开看完整答案

11_doc_loader_splitter.py 三处空白的答案 
# ① TextLoader 加载 Markdown 文件
loader = TextLoader("src/teach_ai/trust_spec.md", encoding="utf-8")

# ② RecursiveCharacterTextSplitter 的三个参数
splitter = RecursiveCharacterTextSplitter(
    chunk_size=200,
    chunk_overlap=30,
    separators=["\n\n", "\n", "。", " ", ""]
)

# ③ 切分 Document 列表（不是字符串！）
chunks = splitter.split_documents(docs)

为什么是 split_documents() 而不是 split_text()？因为输入的 docs 是 list[Document]。split_documents 会保留每个 chunk 的 metadata（来源文件路径），这样后续 RAG 回答时可以显示出处。如果用 split_text()，你需要传入纯字符串，且丢失 metadata。
